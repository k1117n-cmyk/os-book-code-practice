# 仮想OS学習記事 Style Guide

「いちばんやさしい！OS自作超入門」と `os_book_code` を題材にした学習記事を作成・修正する前に確認する文体ガイドです。

対象読者は、書籍を読みながら手元でコマンドを実行している初学者です。記事では、書籍本文と現在のGitHub版コードの前提がずれて見える箇所を、実行手順と確認方法に分けて説明します。

## 基本文体

本文の地の文は「です・ます」調で統一します。

使う表現:

- 追加します
- 確認します
- 表示します
- 見ていきます
- 分かります
- できるようになります
- 公開されています
- 起動します
- 実行します
- 読み込みます

避ける表現:

- 追加する
- 確認する
- 表示する
- 見ていく
- 分かる
- できるようになる
- 公開されている
- 起動する
- 実行する
- 読み込む

## 記事の基本方針

記事は、感想文ではなく「同じ場所で止まった人が原因を切り分けられるメモ」として書きます。

各つまずきは、できるだけ次の順番で整理します。

1. 実行したコマンド
2. 起きたこと
3. 原因
4. 確認方法
5. 対応方法

書籍本文とGitHub最新版の差分を扱う場合は、どちらが間違いかを断定するよりも、「前提にしている実行方法が違います」と説明します。

## 用語の扱い

次の用語は表記をそろえます。

- `os_book_code`
- `asm.py`
- `emu.py`
- `early.py`
- `os.bin`
- `hello.asm`
- `hello.bin`
- `pi.asm`
- `pi.bin`
- Simple OS
- `HALT`
- `RET`
- `SYSCALL`
- `exec`
- `dir/pi.bin`

本文では、ファイル名、コマンド名、命令名、レジスタ名はバッククォートで囲みます。

例:

- `python emu.py hello.bin`
- `R8`
- `PC`
- `HALT`
- `RET`

## コード例

シェルで実行するコマンドは `sh` のコードブロックにします。

```sh
python asm.py hello.asm
python early.py hello.bin
```

OSプロンプトや実行結果は `text` のコードブロックにします。

```text
Welcome to Simple OS!
> exec pi.bin
```

アセンブリの差分は `diff` のコードブロックにします。

```diff
-        HALT
+        RET
```

コマンド例では、読者がどのディレクトリで実行するか迷いやすい場合だけ `cd` を入れます。

```sh
cd /path/to/os_book_code
python emu.py
```

## 実行手順を書くときの注意

現在の `emu.py` は、引数で渡した `.bin` を読むのではなく、カレントディレクトリの `os.bin` を読み込んで Simple OS を起動します。

そのため、書籍序盤の単体プログラムを直接動かす手順では、`early.py` を使う前提で書きます。

```sh
python asm.py hello.asm
python early.py hello.bin
```

Simple OS の `exec` から外部プログラムを動かす手順では、`dir/` への配置を必ず書きます。

```sh
python asm.py pi.asm
mkdir -p dir
cp pi.bin dir/pi.bin
python emu.py
```

OS起動後の入力も分けて書きます。

```text
> exec pi.bin
```

`File open error.` を扱う場合は、`exec` が `dir/<ファイル名>` を読むことを明記します。

## `HALT` と `RET` の説明

`HALT` と `RET` は、実行方法と結びつけて説明します。

- `HALT`: 単体プログラムとして直接実行して、CPUを停止する場合に使います
- `RET`: Simple OS の `exec` から起動して、OSのコマンドループへ戻る場合に使います

`pi.asm` の書籍版とGitHub最新版の差分を説明するときは、次の点を含めます。

- 書籍側は単体実行寄りの説明に見えます
- GitHub最新版は `exec` から起動できるように `RET` へ変更されています
- Git履歴のコミットメッセージは「`execコマンドで起動できるように終了方法を変更`」です

## 許容する箇所

次の箇所では、短いラベルとして常体に近い表現を使ってもかまいません。

- 見出し
- コードブロック内の処理メモ
- コードブロック直前の短いラベル
- リンクテキスト

例:

- 実行コマンド:
- 出力:
- 確認するコード:
- 変更後のコード:

## 公開前チェック

公開前に、本文の地の文に常体が残っていないか確認します。

確認用コマンド:

```sh
rg -n "する。|した。|できる。|分かる。|なった。|ではない。|している。|起動する。|実行する。|読み込む。" articles/*.md
```

検索結果が出た場合でも、コードブロック内、見出し、短いラベル、リンクテキストであれば問題ない場合があります。本文の説明文に残っている場合は、「です・ます」調へ直します。

あわせて、次の観点も確認します。

- 書籍本文の手順とGitHub最新版の挙動を混同していないか
- `emu.py` と `early.py` の役割を取り違えていないか
- `exec` 実行手順に `dir/` への配置が含まれているか
- `HALT` と `RET` の使い分けを実行方法とセットで説明しているか
- エラーを紹介するとき、原因と確認方法を書いているか
