# 「いちばんやさしい！OS自作超入門」第6章でつまずいたこと

書籍「いちばんやさしい！OS自作超入門」を読みながら、`os_book_code` の第6章を進めます。

第6章では、タイマー割り込みを使ったタスク切り替えを拡張し、タスク1からタスク3までを実行できるようにします。

この記事では、第6章を進める中でつまずいた点と、手元で確認した対応を整理します。

## 図11の `_task_switch:` は追加ではなく置き換え

第6章では、図10でタスク1からタスク3の実体コードを追加したあと、`int_timer` のコードを変更します。

ここで注意が必要なのは、図11のコードは、元の `int_timer` 内にある `_task_switch:` 以降を置き換えるコードだという点です。

書籍本文には「元のコードの `_task_switch:` 以降を図11のように変更してください」とあります。つまり、古い `_task_switch:` ブロックを残したまま、図11の新しい `_task_switch:` ブロックを追加してはいけません。

古いコードを残すと、`os.asm` の中に次のラベルが二重に定義されます。

```asm
_task_switch:
_select_next:
_int_timer_end:
int_other:
```

`asm.py` は同じラベル名が複数回出てきてもエラーにせず、後から出てきた定義で `symbol_table` を上書きします。

そのため、前半に書いた新しいタスク切り替え処理へジャンプするつもりでも、実際には後ろに残っていた古い `_task_switch:` 側へ分岐してしまいます。

この状態では、タスク1からタスク3へ正しく切り替わらず、仮想コンソールを切り替えても各タスクのメッセージが表示されませんでした。

確認するときは、次のように `_task_switch:` などのラベルが複数出ていないかを見ます。

```sh
rg -n "^(_task_switch|_select_next|_int_timer_end|int_other):" os.asm
```

正しく置き換えられていれば、それぞれ1回ずつだけ表示されます。

```text
278:_task_switch:
315:_select_next:
322:_int_timer_end:
335:int_other:
```

図12と図13の `Task DATA` セクションは、罫線で囲まれた部分を既存のデータ定義に追加する形です。

一方、図11の `int_timer` の変更は、追加ではなく既存の `_task_switch:` 以降の差し替えとして読む必要があります。

## スタックの `PUSH` と `POP` の数を合わせる

今回の確認では、古い `_task_switch:` ブロックの残存に加えて、スタックの保存と復元がずれる記述もありました。

タスクの初期スタックを作る部分で `R9` を余分に `PUSH` すると、タスク復帰時に `VT`、`PT`、`R9`、`R8` と取り出していく位置が1つずれます。

```asm
PUSH    R0      ; R8
PUSH    R0      ; R9
PUSH    R0      ; R9  ; これは余分
PUSH    R0      ; PT
```

また、`_int_timer_end:` の復元処理でも、`POP R2` が2回あると同じようにスタックがずれます。

```asm
POP     R3
POP     R2
POP     R2      ; これは余分
POP     R1
POP     R0
```

タスク切り替えでは、割り込みで積まれた `PC` と `CR` に加えて、`_task_switch:` 側で保存した汎用レジスタ、`PT`、`VT` を正しい順序で復元する必要があります。

画面が固まって見える場合は、`emu.py` を疑う前に、`os.asm` 側で `PUSH` と `POP` の数が対応しているかを確認します。
