# 自作OS学習メモ

## 目的

このディレクトリは、書籍「いちばんやさしい！OS自作超入門」を読み終えたあとに、自分の理解を確認するためのメモ置き場。

GitHub のコードをただ動かすだけでなく、次の対応関係を自分の言葉で説明できるようにする。

- アセンブリ命令と機械語の対応
- レジスタとメモリの役割
- `asm.py` が何をしているか
- `emu.py` がCPUをどう模擬しているか
- `SYSCALL` がどのようにエミュレータ側の処理につながるか
- 割り込み、タスク切り替え、仮想メモリ、ページフォルトの流れ

## 学習の進め方

最初は小さいプログラムから始める。

```text
hello.asm
  ↓
mul.asm / pi.asm
  ↓
os.asm
  ↓
exec / sleep / task
  ↓
仮想メモリ
  ↓
ページフォルト / デマンドページング
```

書籍の順番で読み進めながら、各段階で次を確認する。

- どの `.asm` をアセンブルしたか
- どの `.bin` ができたか
- `emu.py` はどこから実行を始めたか
- `PC` はどのように進んだか
- `R8`, `R9` は `SYSCALL` でどう使われたか
- スタックに何が積まれたか
- 例外や割り込みで `PC` と `CR` がどう保存されたか

## 重要な観察ポイント

### PC

`PC` は次に実行する命令のアドレス。

`hello.bin` のような単体プログラムでは `PC = 0x00000` が自然。
後半の `os.bin` 起動用では `PC = 0x80000` になっている。

ここが合わないと、命令ではない場所を実行して `Unknown opcode` になりやすい。

### SP

`SP` はスタックポインタ。

`CALL`, `RET`, `PUSH`, `POP`, 割り込み処理で重要。
`push()` では先に `SP` を減らしてから書き込む。

### CR

`CR` は制御レジスタ。

見るところ。

- Zero / Overflow / Underflow フラグ
- 割り込み有効フラグ
- MMU有効フラグ

### R8 / R9

このエミュレータでは `SYSCALL` の引数としてよく使われる。

例。

- `SYSCALL 0`: `R8` の下位8ビットを文字として表示
- `SYSCALL 1`: `R8` が指す文字列を表示
- `SYSCALL 2`: `R8` の値を `R9` が指すフォーマットで表示

## 1-4 / 3-3 Hello, World! の注意点

GitHub の `main` ブランチにある `emu.py` は、後半章向けに `os.bin` を起動する形になっている。

書籍では、1-4「ソースコードの入手とサンプルコードの実行」の時点で、`hello.asm` をアセンブルしてCPUエミュレータで実行する例が載っている。
この出力例は、`hello.bin` を直接読み込む初期版の `emu.py` を前提にしている。

1-4 の `hello.bin` を直接動かす場合は、次の前提が必要。

```python
'SP':  0xFFFFF,
'PC':  0x00000,
```

起動時の読み込みも、`os.bin` 固定ではなく引数指定のファイルを読む。

```python
with open(sys.argv[1], "rb") as file:
```

この形なら、`python emu.py hello.bin` で本当に `hello.bin` が読み込まれる。

このリポジトリでは、この初期版の動きを確認するために `early.py` を用意している。
`hello.bin` を直接実行したい場合は、現行の `emu.py` ではなく次のように実行する。

```sh
python early.py asm_code/hello.bin
```

手元の環境で `python` コマンドが使えない場合は、`python3 early.py asm_code/hello.bin` と読み替える。

現在の配布コードでは、後半章で OS を起動できるように変更されたあとの `emu.py` が入っている。
そのため、読み込み対象は引数ではなく `os.bin` に固定されている。

```python
with open("os.bin", "rb") as file:
```

つまり、書籍の出力例そのものは `hello.bin` 直接実行の結果として正しい。
ただし、現在の配布コードをそのまま使うと、`python emu.py hello.bin` と入力しても `hello.bin` は読まれず、Simple OS が起動する。

書籍1-4の図にある `hello.asm` を直接実行した場合の終了時レジスタは、次の形。

一方、現在の `emu.py` で Simple OS が起動している場合は、`Hello, World!` の直後に `CPU halted.` とレジスタ一覧が表示されるわけではない。
たとえば `python emu.py asm_code/hello.bin` のように引数を渡しても、現行の `emu.py` は `os.bin` を読むため Simple OS が起動する。
プロンプトで `exit` を入力して終了したタイミングで、`bye.` のあと `CPU halted.` と全レジスタのデータが表示される。
